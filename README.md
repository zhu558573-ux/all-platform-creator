# all-platform-creator

这是一份面向支持 `SKILL.md` 的 AI 宿主环境的**提示词与工作流规范**，用于按事实依据写社媒文案、建立个人语感档案，并把同一选题改编到不同平台。

**它不是可独立运行的软件、脚本、命令行工具或浏览器插件。** 单独克隆本仓库不会自动抓取帖子、分析浏览量或发布内容，也不会安装任何第三方导出工具。要使用它，需要一个会读取并遵守 `SKILL.md` 的宿主，以及使用者有权提供或已授权读取的样本与数据。

本仓库中的 `SKILL.md` 已按公开版要求做过修订，不再沿用初版里若干容易引起误解的表述。请把它视为一份由作者整理的工作方法，而不是任何社交平台或上游项目的官方技能。

## 用途

在使用者要求写推文、写文案、拆爆帖、建立或使用个人语感档案、根据真实浏览量优化稿件，或把同一选题一稿多发到 X/Twitter、小红书、B站、抖音/快手/视频号、知乎、微信公众号时，把本技能提供给支持 `SKILL.md` 的宿主加载后使用。

## 能做什么，以及做不到什么

按 `SKILL.md` 的设计，宿主模型在加载本技能后应尝试：

- 先核对事实，不编造浏览量统计表，也不替使用者虚构未发生的经历；
- 按优先级读取个人语感档案，或把空模板复制到用户工作区后协助建档；
- 在有真实浏览量时做描述性的 `Traffic Lift` 对比，并提示样本时间和发帖时长可能带来的偏差；没有数据时跳过表格；
- 按常用题型起草内容，必要时另给评论区 1 楼文案，再按目标平台改写成短帖、长文、图文笔记或口播稿。

以上是技能对宿主的工作流要求，不是已经过独立评测的产品功能清单。实际效果随宿主能力、数据完整度和模型表达而变化。本技能**默认只产出草稿**，不会自动发帖；发布必须由使用者另外给出明确授权。

本仓库没有可执行代码、安装脚本、第三方抓取工具源码，也没有示例账号或真实帖子数据。根目录的 `voice-profile.md` 必须保持为空模板。

## 手动安装

本技能没有官方安装包，也**不提供、不保证**任何 `npx`、`npm`、`pip` 或其他一键安装命令。请按你使用的宿主文档，用下面这类通用方式手动加载，并在自己的环境里核实路径是否正确：

1. 下载或复制本仓库中的 `SKILL.md` 与空模板 `voice-profile.md`。
2. 若宿主使用「技能目录」：新建与技能名一致的文件夹 `all-platform-creator`（须与 `SKILL.md` 文件头中的 `name` 一致），将上述两个文件放入其中。
3. 具体路径因宿主而异，必须以该宿主的说明为准。部分环境会把技能放在配置目录下的 `skills/all-platform-creator/`（例如有的 OpenCode 安装使用 `~/.config/opencode/skills/`，在 Windows 上则位于当前用户的配置目录中）。不要假设某一条固定路径在所有机器上都能生效，也不要假设复制后无需重启或重新索引。
4. 若宿主支持在对话中附加技能文件或手动导入：按该宿主的界面引入即可。
5. 加载后，用该宿主平时调用技能的方式启用（例如在对话里点名本技能，或由宿主按描述自动匹配）。

请不要假设存在应用商店安装，或「复制到某个目录后即可在所有环境生效」。若宿主不支持 `SKILL.md` 技能格式，本文件对它没有约定的运行方式。

## 语感档案与多账号隔离

- 技能目录里的 `voice-profile.md` 永远是空模板，只作复制源。
- 填写后的档案应放在当前项目根目录，或多账号时放在使用者指定的账号专用文件中。
- 读取优先级为：用户明确指定的路径 > 当前项目根目录的 `voice-profile.md` > 经用户选择的账号专用档案。
- 更新档案时只改用户工作区中的副本，严禁写回覆盖技能目录里的空模板，也严禁把一份档案拿去给其他用户或其他未指定的账号使用。
- 建档建议提供 5 至 15 条真实样本；模板预留 5 个样本槽，必要时可继续追加。

## 数据与隐私

- 允许的数据来源只有：用户已授权的连接器或官方接口、当前环境可公开访问的内容、以及用户自己导出或上传的文件与截图。
- 若环境已经能读取使用者授权过的资料，不应再强迫对方把同一份内容重新粘贴一遍。读取失败时必须如实说明，不能假装已经抓到数据。
- `SKILL.md` 里点名的第三方导出插件或 CLI 只是社区参考名称，**不是本仓库的依赖，也没有随仓库发布**。不要在未受用户明确请求时安装它们。即使在用户要求下协助查看安装说明，也**不保证**新安装的插件在其环境中可用。
- 任何取数都只可用于使用者有权访问的账号或公开内容。
- **不要**把已填写的个人语感档案、账号后台截图、帖子导出、密钥、Cookie 或会话一并上传到公开仓库，也不要在 Issue、Pull Request 或示例里粘贴可识别到真人的账号记录。

## 相对初版的主要改进

对比最初以 `xhs-bilibili-creator` 为名的那一版，公开稿主要做了这些调整：

- 技能名、目录名与仓库名统一为 `all-platform-creator`，与实际覆盖的多平台内容一致。
- `description` 改为较短的触发词描述，便于宿主发现和调用。
- 明确语感档案的读取优先级、空模板不得写回覆盖，以及多账号隔离规则。
- 空模板样本槽从 4 个扩到 5 个，并补充「5 至 15 条真实样本、可继续追加」的说明；模糊的「配套文件」说法改为「本技能目录下的同级模板」。
- 纠正了初版里未核实的绝对算法主张，例如不能把「双向评论 / 书签权重最高」或「外链必然降权」当成事实。
- `Traffic Lift` 只作为描述性对比，不作因果归因；补充样本时间和发帖时长偏差提示，无数据时跳过。
- 取数规则改为按运行环境的真实能力，不擅自安装抓取工具，也不再暗示本技能「完整内嵌」了开源抓取生态。
- 对 `khazix-skills`、`humanizer-zh` 等上游方法，改为「使用者提供的工作方法摘要 / 灵感」，不再声称完整原版或把仅有的 4 条摘要写成「24 类完整内嵌」，也不假冒官方技能。
- 明确拟稿与已发布样本必须分开，发帖需要用户另行授权，默认不自动发布。

## 限制与重要声明

请把 `SKILL.md` 当作一套**作者自行整理的操作规范与启发式规则**，而不是 X、小红书、B站或其他平台官方文档的转述，也不是已经过验证的推荐算法说明。

尤其需要注意：

- 评论、书签或其他互动是否提高推荐，以及主帖放入站外链接会不会被降权，都不是本技能可以证实的普遍规则；
- `Traffic Lift` 只能比较已有样本里的相对浏览量，不能证明流量来源，也不能证明某种写法造成了结果；
- 技能中的题型、转译轨道和去套话摘要都是写作建议，效果因账号、平台和时期而异；
- 本技能不保证提升浏览量、粉丝或收入，也不保证在某一个宿主上加载后一定按原文逐步执行。

X、小红书、B站、抖音、快手、视频号、知乎、微信及其他被提及产品的名称、政策和界面都会变化；现行规则请以各平台当前公布的文件为准。本仓库与这些平台以及 `khazix-skills`、`humanizer-zh` 等上游项目都没有从属或官方认证关系。
